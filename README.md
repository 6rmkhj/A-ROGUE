# A:\ROGUE

1.44MB 게임 개발 공모전을 위한 Win32/GDI 로그라이트입니다. 외부 엔진, 이미지, 폰트 파일, 사운드 파일 없이 실행되며 그래픽과 효과음은 Windows API로 생성합니다.

## 구현 범위

- 3개 주사위 × 6면의 18면 덱
- 숫자 및 특수 면 8종
- 공격·방어·증폭·연쇄 슬롯
- 드라이브 6종마다 전용 일반 몹 3종 + 층별 보스 3종 (활성 36종, 레거시 11종 보존)
- 고유 기믹 18종: 슬롯 잠금, 복원·되감기, 주사위 오프라인, 해결 순서 역전, 메모리 압력, 면 격리·영구 삭제 — 모두 발동 전 예고
- 기믹 발동 연출 18종: 예비 동작 → 히트스톱 임팩트 → 동작 → 여운의 골격을 공유하고, 사건이 난 자리에서 시작한다. 잠금은 보스 카드에서 신호가 내려와 층마다 다른 철문(마름모 격자 → 골판 → 단열 슬랫)이 칸을 덮고, 오프라인은 주사위 카드가 갈라지며 뽑히고, 경로는 슬롯 아래 배선과 사이드바 실행 순서가 갈렸다 재조립되며, 압력은 초상이 부풀고, 격리는 봉인 링이 조여든다. 프레임 스냅샷으로 잔상·데이터모싱을 내고 초상은 늘어났다 돌아온다. 전체 화면은 되돌릴 수 없는 `ZERO.DAY`와 판을 바꾸는 발동뿐 (BSOD는 전투당 한 번)
- 로스터 판독: 가이드 2페이지의 적·보스 6종이 헥스 노이즈로 덮여 있다가, 처치한 종류만 노이즈가 걷히며 정보가 열림 (런 단위)
- 36종 전용 + UNKNOWN 폴백의 16×16 코드 도트 초상 (총 48종)
- 3층 × 일반 전투 2회 + 보스전 (일반 몹은 시드 순서로 각 2회 등장)
- 층마다 두 번, 일반전 직전에 고르는 **하위 디렉터리 2택** (PROCESS · TEMP · CACHE · LOGS · INFECTED · CORRUPTED)
  - 노드는 면이나 상주 프로그램을 직접 주지 않고 다음 전투와 그 보상의 조건만 바꾼다
  - 위험·비용·보상 tier는 카드에 전부 공개되고, 가려지는 것은 아직 판독하지 않은 적 코드뿐이다
  - 드라이브마다 고정 가중치가 달라 같은 층이라도 볼륨별로 다른 선택지가 나온다
  - 경로 전용 난수열을 쓰므로 주사위·보상 난수 순서는 그대로다
  - 보스 앞에는 선택 화면이 없다 (고정 경로)
- 런마다 선택되는 디스크 손상 5종 중 2종
- 드라이브 카드 3장에 겹치지 않게 배정되는 볼륨 난이도 5등급 (초급자 25 · 중급자 50 · 전문가 75 · 악몽 100 · 광기 200 = 오염(관통) 피해 %)
- 관통 피해는 방어도를 절반만 인정 (막아낸 몫의 두 배가 방어도에서 소모)
- 보상 면 설치, 층간 용량 정리(삭제한 면 재클릭으로 복원), 승리·패배·재시작
- 실행 전 미리보기: 배치를 바꿀 때마다 슬롯별 예상 산출량과 `적 체력 -N · 내 체력 -M · 획득 방어도 B`를 표시 (판독 후에만, 읽기 오류가 있으면 흔들리는 값이 닿는 슬롯과 총합을 `?`로 가리고 확정 아님으로 표기)
- 턴 계산 재생: 현재 계산 줄은 적 카드와 슬롯 사이의 티커에, 최근 내역과 진행도는 오른쪽 패널에 표시되어 재생 중에도 전투판 전체가 보임
- 전투 연출: 규칙이 확정한 사건(증폭·공격·적중·방어·연쇄·화상·적 행동)을 계산 줄 번호와 함께 기록해 두고, 재생이 그 줄에 닿는 순간 신호 경로·충격·파편·체력 잔상·피해 숫자를 그 자리에서 재생 — 숫자를 읽지 않아도 작은 피해·큰 피해·처치가 구별됨
- 피격 연출: 계산 재생이 자기 행동 줄에 닿는 순간 적이 달려들고, 화면 흔들림·붉은 테두리·피해 표시가 함께 터짐
- 다수 적 전투: X:\ 2층 SANDBOX.BREACH가 3턴마다 검체를 탈주시킨다. 탈주체까지
  전부 쓰러뜨려야 전투가 끝나고, 보스를 먼저 끊으면 소환이 멈춘다. 적이 둘 이상이면
  연쇄는 대상이 아닌 쪽으로 튄다
- 연출 강도 설정 (FULL / REDUCED / OFF): 줄어드는 것은 흔들림·파편·전역 글리치뿐이고, 슬롯 잠금·오프라인 주사위·격리 대상 면·해결 순서·압력 게이지·체력 잔상과 피해 숫자는 모든 모드에서 유지
- 소리 크기 슬라이더 (0~100%): 믹서 단계에서 걸리는 마스터 볼륨이라 울리는 중인 소리에도 바로 적용된다. 끌거나 좌우 방향키로 조절하고, 기본값은 50%
- 체력 10 이하부터 화면 가장자리가 무너지고, 체력 1에서는 버틸수록 그 띠가 두꺼워짐 (판 중앙은 유지)
- 체력 0이면 그 노이즈가 풀려나 화면을 가장자리부터 갉아먹고, 다 삼킨 뒤 재시작 화면으로 전환
- GDI 더블 버퍼링 UI, 코드로 그리는 도트 초상, 메모리에서 합성되는 효과음
- 드라이브별 VOLUME LAW, 보스/선택 LOGS 스토리, 두 갈래 엔딩
- 외부 음원 없는 4채널 절차적 BGM과 전투 intensity·위독 편곡·SFX ducking

상세 규칙은 [RULEBOOK.md](RULEBOOK.md)를 참고하세요.

## 빌드

Visual Studio Build Tools와 `Desktop development with C++` 구성요소가 설치된 Windows에서 실행합니다.

```bat
build-msvc.bat
```

스크립트는 다음을 자동으로 수행합니다.

1. `vswhere`로 MSVC를 찾고 x64 환경을 설정
2. `/MT`, `/utf-8`, 크기 최적화로 `build\AROGUE.exe` 생성
3. 결정론적 스모크 테스트: 로스터·초상화 무결성, 드라이브별 스폰 매트릭스, 18개 보스 기믹 시나리오, 디렉터리 생성·전이·노드 효과, 모든 손상 조합·6드라이브 전체 런
4. 드라이브별 300시드(총 1,800런) 휴리스틱 밸런스 검사 — 드라이브 승률 20~80%, 격차 30%p 이하, 모든 법칙 발동, 모든 난이도 승리, 모든 노드 제시를 검사
5. BGM 감상 도구 `build\wav.exe` 빌드 (실행은 하지 않음 — `build\wav.exe <폴더>`로 드라이브별 40초 WAV와 구조 로그를 뽑는다)
6. EXE의 정확한 바이트 수와 1,474,560B 대비 비율 출력 — 한도를 넘으면 빌드 실패

MinGW-w64가 이미 설치된 환경에서는 `build.bat`을 사용할 수 있습니다.

## 제출 패키지

`build\AROGUE.exe`만 제출 패키지에 포함하면 됩니다. PDB, OBJ, 스모크 테스트 실행 파일과 소스는 실행에 필요하지 않습니다. 공식 한도는 압축 해제 후 전체 1,474,560바이트입니다.
# VOLUME LAW, 스토리, 절차적 BGM

각 드라이브는 기존 패시브와 별도로 전투 배치를 바꾸는 고유 `VOLUME LAW`를 가집니다.

- C `VERIFIED EXECUTION`: 가장 낮은 양수 기본 출력 하나 +1
- D `SNAPSHOT`: 직전 실행과 같은 die→slot 배치 하나 +2
- E `HOT SWAP`: 이미 배치한 주사위를 옮기면 턴당 한 번 전용 RNG 재굴림
- N `PACKET CHAIN`: CHAIN 외 유효 슬롯 둘 이상일 때 같은 연쇄 한 번 추가
- R `VOLATILE MEMORY`: 공격·증폭 기본 출력 +1, 적 행동 전 방어도 절반 휘발
- X `CONTRABAND`: 시작 압수 면 +2, 사용 뒤 다음 한 턴 격리

새 런은 부팅 기록에서 시작합니다. 보스 기록, 선택형 `LOGS`, 최종 진실을 복구한 뒤
`RESTORE HOST`와 `EXEC ROGUE` 중 하나를 선택해야 승리 화면에 도달합니다.

음악은 외부 음원 없이 22.05kHz 모노로 실시간 합성됩니다. 여섯 드라이브의 BPM과
패턴, 전투 위험도, 보스 체력, 위독 상태, 스토리/엔딩에 반응하며 설정에서 BGM만 끌 수
있습니다. 기존 소리 슬라이더는 BGM과 효과음에 함께 적용되는 마스터 볼륨입니다.
